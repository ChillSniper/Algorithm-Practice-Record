# List of ByteDance

## 小于n的最大数

给定一个数n，比如23121，给定一组数字a，比如{2, 4, 9}，求a中元素组成的小于n的最大数，比如小于23121的最大数为22999

- [ ] LeetCode 902. 最大为 N 的数字组合 (Numbers At Most N Given Digit Set)

- [ ] LeetCode 738. 单调递增的数字 (Monotone Increasing Digits)

- [ ] LeetCode 681. 最近时刻 (Next Closest Time)

- [ ] LeetCode 31. 下一个排列 (Next Permutation)

---

字节跳动的算法面试在业界以**难度大、覆盖广、要求手撕无 Bug**著称。除了你刚才问的这道“小于N的最大数”之外，字节跳动题库中有几道常年霸榜的**必考题**。

根据近几年的面经统计，以下几道题可以说是字节面试的“敲门砖”，如果准备去字节，**这些题必须熟练到能肌肉记忆般手写出来**：

## 1. 数据结构设计

   **[LeetCode 146] LRU 缓存机制**
       **字节爱考原因**：这题完美考察了哈希表和双向链表的结合，代码量适中，边界条件多，极度考验工程实现能力。
       **进阶考法**：经常会让你自己实现双向链表，而不是用语言自带的现成库（如 Java 的 `LinkedHashMap`）。甚至有时会作为 Hard 难度的 **[LeetCode 460] LFU 缓存** 出现。

## 2. 链表操作

   **[LeetCode 25] K 个一组翻转链表**
       **字节爱考原因**：链表题的集大成者。考察指针操作的最强题目，很容易出现断链、死循环等问题。字节非常喜欢看候选人处理这种细致逻辑的表现。
       **相关必刷**：反转链表（LC 206）、合并K个升序链表（LC 23）。

## 3. 排序与分治

   **[LeetCode 215] 数组中的第K个最大元素**
       **字节爱考原因**：快排（Quick Sort）及其变体（Quick Select）是字节的底线。面试官经常要求不能用堆，必须用**基于快速排序的选择方法**，并且要求分析时间复杂度为什么是 $O(N)$。

## 4. 树的遍历与查找

   **[LeetCode 103] 二叉树的锯齿形层序遍历 (Zigzag Level Order)**
       **字节爱考原因**：在普通 BFS 的基础上加了小变形，考察对队列、双端队列的使用以及层次变量的控制。
   **[LeetCode 236] 二叉树的最近公共祖先**
       **字节爱考原因**：递归思想的经典体现，代码极短，但如果不理解递归栈的回归过程根本写不出，非常考验对树状结构的理解。

## 5. 双指针与滑动窗口

   **[LeetCode 3] 无重复字符的最长子串**
       **字节爱考原因**：滑动窗口的入门兼终极经典题。面试官很喜欢看你对窗口左边界移动策略的优化（比如直接用 HashMap 记录索引跳跃，而不是一步一步滑动 `left`）。
   **[LeetCode 42] 接雨水**
       **字节爱考原因**：Hard 题常客。可以考察动态规划、单调栈、双指针三种解法。面试官通常会让你先写一个空间复杂度 $O(N)$ 的解法，然后逼问你怎么优化到 $O(1)$（双指针法）。

## 6. 动态规划经典场景

   **[LeetCode 121 / 122 / 188] 买卖股票的最佳时机系列**
       **字节爱考原因**：状态机 DP 的最好代表。面试官经常会从只能买卖1次（LC 121），一直问到可以买卖K次（LC 188），考察你对状态定义（持有/不持有）的抽象能力。
   **[LeetCode 72] 编辑距离**
       **字节爱考原因**：二维 DP 的老牌强题，考察对状态转移方程的设计，以及如何处理字符串的增删改。

---

除了前面提到的绝对核心（LRU、K个一组反转链表、快排、接雨水等），字节跳动的庞大题库中还有以下几个重灾区。我将按**常考的数据结构和算法分类**为你一一列举这些高频题（附带 LeetCode 题号）：

## 1. 二分查找系列（边界处理的试金石）

字节极其看重二分查找中对 `left` 和 `right` 边界、以及 `while(left < right)` 还是 `<= right` 的掌控力。
   **[LeetCode 33] 搜索旋转排序数组**：二分法的集大成者，要求 $O(\log n)$，必须清楚如何判断哪一半是有序的。
   **[LeetCode 4] 寻找两个正序数组的中位数**：Hard题，字节非常喜欢在二面/三面考，要求 $O(\log(m+n))$ 时间复杂度，极度考验对二分逻辑的理解。
   **[LeetCode 162] 寻找峰值**：二分法不仅能用于有序数组，还能用于这种局部有序的题目。

## 2. 字符串与双指针（常考手撕基本功）

这部分题目通常不难，但要求**边界清晰、Bug-Free、并且不能用语言内置函数**。
   **[LeetCode 15] 三数之和**：排序 + 双指针去重。极其高频，经常要求手撕并详细解释如何跳过重复数字。
   **[LeetCode 5] 最长回文子串**：中心扩展法是标准答案，偶尔会有面试官要求讲讲 Manacher（马拉车）算法的思路。
   **[LeetCode 415] 字符串相加**（大数相加）：高频基础题！常考变形有“大数相乘”、“大数相减”，全面考察进位（carry）处理。

## 3. DFS / 回溯算法（暴力搜索的优雅实现）

   **[LeetCode 46] 全排列**：回溯算法的“Hello World”。延伸变种：有重复数字的全排列（LC 47，考察剪枝）。
   **[LeetCode 200] 岛屿数量**：网格类 DFS/BFS 的万恶之源。延伸变种：岛屿的最大面积（LC 695）。
   **[LeetCode 93] 复原 IP 地址**：经典回溯，考验字符串截取和合法性判断。

## 4. 栈与单调栈（考察思维转换）

   **[LeetCode 20] 有效的括号**：极其基础，但经常作为热身题出现，几分钟写不出来大概率直接挂。
   **[LeetCode 739] 每日温度**：**单调栈**的入门必刷题，遇到“寻找下一个更大/更小元素”的场景必用。
   **[LeetCode 84] 柱状图中最大的矩形**：单调栈的 Hard 题，字节喜欢拿这道题来压榨候选人的逻辑上限。

## 5. 动态规划（子序列与背包模型）

除了前面提过的买卖股票系列和编辑距离，下面这两道也是必考：
   **[LeetCode 300] 最长递增子序列 (LIS)**：经典 DP。进阶考法：要求写出 $O(n \log n)$ 复杂度的贪心 + 二分查找解法。
   **[LeetCode 1143] 最长公共子序列 (LCS)**：二维 DP 的基础题，经常和字符串匹配结合考察。

## 6. 原地哈希 / 数组操作

   **[LeetCode 41] 缺失的第一个正数**：Hard题。要求 $O(N)$ 时间和 $O(1)$ 空间。非常巧妙的“原地哈希”思想（把数字 `i` 放到下标 `i-1` 的位置上），没做过的话面试现场几乎想不出来。
   **[LeetCode 56] 合并区间**：按左端点排序然后贪心合并。代码简单，考察日常工程思维。

**建议复习策略**：如果在牛客网或者 LeetCode 的“企业题库”里按照字节跳动的频率倒序刷，前 50-80 道题基本就可以覆盖上面列出的绝大部分内容。

在字节跳动的面试中，随着轮次的深入（尤其是二面和三面），面试官的考察重点往往会从纯算法题（LeetCode 类的逻辑推导）转向**工程能力、并发控制以及系统设计**。

---

结合近期的真实面经，以下是除了传统算法题外，字节跳动非常喜欢考的**并发编程、代码设计以及场景题**：

## 1. 多线程与并发编程（手撕代码）

字节跳动非常看重候选人对线程同步、锁机制和并发容器的理解。通常不让你用现成的高级并发库，而是要求用最基础的锁/信号量来实现。

   **交替打印系列（LeetCode 并发专区）**
       **经典考法**：[LeetCode 1114] 按序打印、[LeetCode 1115] 交替打印 FooBar、交替打印 ABC（线程1打印A，线程2打印B，线程3打印C，循环10次）。
       **考察点**：考察对 `synchronized` / `wait()` / `notifyAll()`（Java），或者 `mutex` / `condition_variable`（C++），或者 `channel` / `sync.WaitGroup`（Go）的熟练度。
   **手写生产者-消费者模型**
       **经典考法**：不用语言自带的阻塞队列（如 Java 的 `BlockingQueue`），手动用一把锁和条件变量实现一个定长队列，包含 `put()` 和 `take()` 方法，支持多线程安全调用。
   **多线程并发控制 / 任务调度**
       **经典考法**：实现一个异步任务执行器（Promise / 线程池）。比如前端常考“手写并发请求控制（限制最大并发数为 N）”；后端常考“如何优雅地等待多个并发任务全部执行完毕并汇总结果”。

## 2. 面向对象与数据结构设计（工程题）

这类题目要求你设计一个类，内部封装好数据结构，暴露特定的 API，并且对时间/空间复杂度有苛刻要求。

   **带过期时间的 LRU 缓存**
       **经典考法**：在标准 LRU 的基础上，增加一个 `TTL（Time to Live）` 参数。要求 `get()` 时如果数据已过期则返回 -1，并清理空间。
       **考察点**：数据结构设计 + 惰性删除（查询时检查过期）或定期清理（后台线程）。
   **[LeetCode 380] O(1) 时间插入、删除和获取随机元素**
       **经典考法**：要求在 $O(1)$ 时间内完成。核心思想是利用哈希表记录值和数组下标的映射，删除时将数组末尾元素填补到被删位置。
   **前缀树（Trie）的应用**
       **经典考法**：[LeetCode 208] 实现 Trie (前缀树)。进阶可能考“敏感词过滤系统”、“搜索引擎的搜索补全（联想词）”。
   **实现一个简单的限流器 (Rate Limiter)**
       **经典考法**：手撕“令牌桶（Token Bucket）”或“滑动窗口（Sliding Window）”算法。经常在后端面试中要求写出伪代码。

## 3. 海量数据处理（单机内存受限场景）

这是大厂的传统保留项目，主要考察“分治思想”和“哈希映射”。

   **经典考法 1：100亿个URL，内存只有 1GB，如何找出出现频率最高的 Top 100？**
       **标准解法**：哈希分流（Hash将大文件拆分成多个小文件） -> 小文件内用 HashMap 统计频率 -> 维护一个大小为 100 的小顶堆求局部 Top 100 -> 最后合并。
   **经典考法 2：40亿个无符号整数，内存只有 1GB，如何判断一个数是否存在？**
       **标准解法**：位图（BitMap）。如果数据稀疏或者要求低碰撞，可能会引申到布隆过滤器（Bloom Filter）。

## 4. 场景设计题（系统架构）

对于校招偏后期的轮次或社招，面试官会给一个实际业务场景，让你设计系统。

   **设计短链系统 (TinyURL)**
       **考察点**：长链与短链的映射关系存储、发号器设计（全局唯一 ID 生成，如雪花算法）、Base62 编码转换、高并发读的缓存策略（Redis）。
   **设计排行榜系统**
       **考察点**：百万级用户的实时积分排行。标准答案通常指向 Redis 的 `ZSet`（跳表数据结构），面试官会追问 ZSet 的底层实现（SkipList + Dict）。
   **扫码登录的完整流程**
       **考察点**：状态轮询/长连接（WebSocket）、Token 的生成与校验、移动端与 Web 端的会话同步机制。

**总结建议**：
去字节面试，**第一轮通常是纯算法**（双指针、DP、树）。如果顺利进入**第二/三轮**，面试官发现你算法不错后，大概率会掏出**多线程交替打印、LRU变种、手写生产者消费者**这种带有工程属性的题目。建议专门在 IDE 里空手多敲几次这类多线程代码，确保没有死锁和虚假唤醒问题。

---

在字节跳动的面试中，算法题的考察往往具有**“分类明确、覆盖面广、极其注重细节”**的特点。根据各个算法大类，以下为你详细列举字节高频考察的 LeetCode 经典题单：

## 1. 多维动态规划 (Multi-dimensional DP)

除了前文提到的最长公共子序列和编辑距离，以下几道也是重灾区：
   **[LeetCode 5] 最长回文子串**：除了中心扩展，DP 解法也是常考点。
   **[LeetCode 10] 正则表达式匹配**：Hard题。二维 DP 的天花板，考察对 `*` 和 `.` 状态转移的极度细致推导。
   **[LeetCode 64] 最小路径和**：基础的网格 DP。
   **[LeetCode 322] 零钱兑换**：完全背包问题的最经典代表。

## 2. 链表 (LinkedList)

字节对链表的考察极其严格，要求指针操作绝对不能出现空指针异常（NPE）。
   **[LeetCode 142] 环形链表 II**：找到入环点。常被要求证明为什么快慢指针相遇后，一个从头走，一个从相遇点走，一定会在入环点相遇。
   **[LeetCode 143] 重排链表**：综合题（找中点 + 反转后半段 + 交叉合并）。
   **[LeetCode 160] 相交链表**：双指针走 `A+B` 路径的经典操作。
   **[LeetCode 82] 删除排序链表中的重复元素 II**：考察哑节点（Dummy Node）的使用。

## 3. 二叉树 (Binary Tree)

树的题目重在递归思想（DFS）和层序遍历（BFS）。
   **[LeetCode 124] 二叉树中的最大路径和**：Hard题，非常高频。自底向上的递归，考察对路径定义的理解。
   **[LeetCode 199] 二叉树的右视图**：层序遍历取每层最后一个元素，或者先右后左的 DFS。
   **[LeetCode 543] 二叉树的直径**：求最大深度的变体。
   **[LeetCode 114] 二叉树展开为链表**：考察前序遍历的巧妙变形，进阶要求空间复杂度 $O(1)$。

## 4. 贪心算法 (Greedy)

   **[LeetCode 55 / 45] 跳跃游戏 I & II**：贪心记录当前能到达的最远距离。
   **[LeetCode 134] 加油站**：考察对贪心局部的判断（如果 A 到不了 B，那么 A 到 B 之间的任何点都到不了 B）。
   **[LeetCode 763] 划分字母区间**：贪心 + 哈希表记录字符最后出现的位置。

## 5. 回溯算法 (Backtracking)

   **[LeetCode 22] 括号生成**：控制左括号和右括号的数量进行 DFS。
   **[LeetCode 39 / 40] 组合总和 I & II**：考察如何用起始索引 `startIndex` 去重，以及排序后剪枝。
   **[LeetCode 79] 单词搜索**：网格中的回溯，必须记得撤销状态。

## 6. 二分查找 (Binary Search)

   **[LeetCode 74 / 240] 搜索二维矩阵 I & II**：矩阵二分的经典，特别是 II 要求从右上角或左下角开始搜索的“Z字形查找”。
   **[LeetCode 153] 寻找旋转排序数组中的最小值**：二分法找无序点。
   **[LeetCode 69] x 的平方根**：要求手写，注意整型溢出死循环等边界问题。

## 7. 前缀和 (Prefix Sum)

   **[LeetCode 560] 和为 K 的子数组**：前缀和 + HashMap，极度高频。不能用滑动窗口因为有负数。
   **[LeetCode 238] 除自身以外数组的乘积**：左右前缀积的巧妙应用，要求 $O(1)$ 额外空间。

## 8. 图论 (Graph)

字节考图论不算特别深，通常局限于拓扑排序和简单的并查集。
   **[LeetCode 207 / 210] 课程表 I & II**：**拓扑排序**的必考题。可以用 BFS（入度表）或 DFS 实现。
   **[LeetCode 695] 岛屿的最大面积**：网格图的连通块问题。
   **[LeetCode 547] 省份数量**：考察并查集（Union-Find）的模板书写。

## 9. 栈与堆 (Stack & Heap)

   **[LeetCode 224 / 227] 基本计算器**：处理加减乘除和括号。后端开发非常喜欢考这道工程解析题。
   **[LeetCode 239] 滑动窗口最大值**：Hard题。单调队列（Deque）的巅峰之作。
   **[LeetCode 295] 数据流的中位数**：Hard题。大顶堆 + 小顶堆的经典搭配，要求极高的插入效率。

## 10. 技巧题 / 数学 / 脑筋急转弯

这类题目通常代码很短，但要想出那个“点”很难。
   **[LeetCode 136] 只出现一次的数字**：异或运算 `^` 的经典应用。
   **[LeetCode 470] 用 Rand7() 实现 Rand10()**：极度高频的数学/概率题。考察拒绝采样（Rejection Sampling），还要会算期望调用次数。
   **[LeetCode 31] 下一个排列**：从后向前找升序对，交换后反转后缀。逻辑推导的经典。
